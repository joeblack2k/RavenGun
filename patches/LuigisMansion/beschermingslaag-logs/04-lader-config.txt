########## patches/LuigisMansion/dropin/dropin.ini ##########
; Drop-in van RavenGun voor Luigi's Mansion Arcade (Sega Nu 1.1, x64 PE onder Wine).
;
; Twee bestanden, en ze horen bij elkaar:
;   rg-pe-hook.dll     onze generieke PE-inline-hook (tools/rt-hasphook/rg_pe_hook*.c)
;   dongle-haken.ini   de 17 adressen plus per functie het antwoord (of TODO)
;
; WAT DEZE DROP-IN DOET
; ---------------------
; De 17 `am`-functies van VACUUM.exe hebben een gewone functieprologue. De GESLOTEN kern vervangt
; die 17 door `e9 <rel32>` naar zijn eigen pagina op 0x13fff0000; ONZE kern doet dat niet, en dan
; roept het spel de echte code aan, vindt geen dongle, en stopt (exit 32, zie EXITBESLUIT.md). Deze
; drop-in laat ONZE hook hetzelfde doen als de gesloten kern: per functie een stub met het antwoord.
;
; WAAROM GEEN DllOverride
; -----------------------
; `DllOverride` zet WINEDLLOVERRIDES en be√Ønvloedt welke DLL het spel bij NAAM importeert. Dat is
; hier niet het kanaal: VACUUM.exe importeert deze DLL niet. Het bewezen kanaal (B0-LEGE-DLL.md) is
; de lader: `OpenParrotLoader64.exe <kern-DLL> <exe>` laadt √©√©n DLL in het spelproces, en de kern is
; niets anders dan `argv[1]` van die lader. Deze DLL moet dus in de plaats van (of naast) de kern
; geladen worden -- dat is een keuze van de launcher, en dat is het enige punt dat nog niet vastligt.
;
; HOE JE CONTROLEERT DAT HIJ GELADEN IS
; -------------------------------------
;   1. `scripts/launch-direct.py LuigisMansion --plan` toont bij `dropins` per bestand de `dest`;
;      staat `rg-pe-hook.dll` daar, dan rolt de drop-in uit;
;   2. in het spelproces verschijnt `rg-pe-hook.log` in de werkmap (de view). Zonder dat logboek is
;      de DLL niet geladen -- en dat is iets anders dan "hij vond niets", want de hook schrijft
;      altijd eerst een PE-regel met ImageBase en SizeOfImage;
;   3. het logboek noemt per adres het oordeel, en in de samenvatting
;      `totaal aangehaakt: N van 17; afgekeurd: M; waarvan antwoord TODO: K`.
;
; LET OP: onder de GESLOTEN kern staan de prologues al op `e9`, en dan WEIGERT onze hook ze met
; "al door een andere kern omgezet?" in plaats van een ketting van twee vervangingen te bouwen. Een
; run met deze drop-in hoort dus met ONZE kern te gebeuren.

[rg-pe-hook.dll]
To = .
Preload = true
; Audit = false: dit is een Windows-PE-DLL, geen ELF. In LD_AUDIT weigert glibc hem met
; "wrong ELF class" en dat is alleen ruis. Preload = true laat het pad in RG_DROPIN_PRELOAD
; staan, en dat is het kanaal dat de lader gebruikt (TP_PRELOAD_DLL). Patroon overgenomen
; van de inline-hook van Halo en JurassicPark (docs/dropins.md, "Audit = false").
Audit = false
Env = RG_HOOK_INI=Z:\home\deck\.local\share\ravengun\runtime\views\LuigisMansion\exe\x64\dongle-haken.ini;RG_HOOK_LOG=Z:\home\deck\.local\share\ravengun\runtime\views\LuigisMansion\exe\x64\rg-pe-hook.log;RG_HOOK_BYTES_LOG=Z:\home\deck\.local\share\ravengun\runtime\views\LuigisMansion\exe\x64\rg-pe-hook-bytes.txt;RG_HOOK_IMAGE=Z:\home\deck\.local\share\ravengun\runtime\views\LuigisMansion\exe\x64\VACUUM.exe

; De adreslijst moet in de view staan, want de DLL leest hem daar (relatief, net als de
; donglegegevens van Halo: de werkmap van het spelproces is de view).
